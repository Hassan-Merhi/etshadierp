# Phase 7D — Excel/PDF Generation and Streaming

Phase 7D adds shared export-response safeguards and a direct ExcelJS streaming helper.

## Implemented

- Factory PDF/XLSX responses automatically receive:
  - `Cache-Control: private, no-store, max-age=0`
  - `Pragma: no-cache`
  - `X-Accel-Buffering: no`
- `streamExcelWorkbook()` writes an ExcelJS workbook directly to the HTTP response instead of first creating a second full workbook buffer.
- The helper ends the response only when ExcelJS has finished and the response is still open.
- PDF responses can use `preparePdfStream()` to apply the same hardened headers before piping the PDF document.
- Regression tests cover content-type detection, response hardening, direct workbook writes, and response completion.

## Safety boundaries

- Existing report calculations, workbook layouts, PDF layouts, filenames, permissions, and route authorization are unchanged.
- No provider, proxy, database, or deployment setting is modified.
- Existing routes that deliberately need a Buffer for WhatsApp, attachments, or another downstream API remain buffered.
- Route-by-route conversion to `streamExcelWorkbook()` should only be done where the workbook is sent directly to the browser and the route does not reuse the generated bytes.

## Operational note

`X-Accel-Buffering: no` is advisory and is honored only by compatible reverse proxies. The code does not claim that any external proxy or hosting provider has been operationally validated.
